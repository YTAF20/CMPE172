1. Logging Plan
------------------------------------------------------------

SLF4J with Spring Boot's default Logback backend. All logging is in
AppointmentService, the one class where booking state changes.

Log level (application.properties):  logging.level.com.advising=INFO

  INFO  — Booking attempt received (start of bookAppointment(), before state is read)
          14:03:22 INFO  [c.a.s.service.AppointmentService] -
            Booking attempt: student=Alice Nguyen slotId=2

  WARN  — Booking rejected (slot gone or version conflict; expected edge case, not an error)
          14:03:22 WARN  [c.a.s.service.AppointmentService] -
            Booking failed: slot 2 not found or already booked

          14:03:22 WARN  [c.a.s.service.AppointmentService] -
            Booking failed: version conflict on slot 2 (concurrent booking detected)

          14:03:23 INFO  [c.a.s.service.AppointmentService] -

2. Monitoring Metrics
------------------------------------------------------------

Two AtomicLong counters in AppointmentService, exposed via GET /health.

  successfulBookings — cumulative completed bookings since startup
  failedBookings     — cumulative rejected attempts (slot gone or lock conflict);
                       a sudden spike indicates high contention or a bug

GET /health sample response:

  {
    "status": "UP",
    "bookings_total": 3,
    "bookings_failed": 1,
    "bookings_attempted": 4,
    "slots_available": 4
  }

------------------------------------------------------------
3. Failure Scenario + Recovery Strategy
------------------------------------------------------------

Scenario: Notification Service is down

  1. Student submits a booking form.
  2. AppointmentService marks the slot booked and saves the Appointment — both
     writes commit via @Transactional.
  3. NotificationClient.send() throws a connection exception.
  4. Without handling this the exception rolls back the transaction, losing the slot.

Recovery: the try/catch around notifClient.send() catches the exception without
re-throwing it. The booking is preserved and the return value is set to
"NOTIFICATION_ERROR" so the controller shows: "Appointment booked — confirmation
email may be delayed." The ERROR log records the appointment ID so the
notification can be replayed manually if needed.

------------------------------------------------------------
4. Health Check Endpoint
------------------------------------------------------------

Endpoint:   GET /health
Controller: HealthController.java
Returns:    JSON (200 OK)

  status             — always "UP" while the process is running
  bookings_total     — completed bookings this session
  bookings_failed    — rejected attempts this session
  bookings_attempted — total booking calls received
  slots_available    — open slots remaining (0 means all filled)

Designed to be polled by an external monitor (e.g. UptimeRobot, load balancer
health probe). A non-200 or status != "UP" signals an unhealthy instance.

--- AppointmentService.java ---
// Declares the logger and three counters that track every booking attempt, success, and failure.

  private static final Logger log = LoggerFactory.getLogger(AppointmentService.class);

  private final AtomicLong totalAttempts      = new AtomicLong(0);
  private final AtomicLong successfulBookings = new AtomicLong(0);
  private final AtomicLong failedBookings     = new AtomicLong(0);

// bookAppointment() emits an INFO on entry, a WARN on each failure path, an ERROR if the
// notification call throws, and a final INFO on success — counters increment at each branch.

  @Transactional
  public String bookAppointment(Long slotId, String studentName) {
      totalAttempts.incrementAndGet();
      log.info("Booking attempt: student={} slotId={}", studentName, slotId);

      Optional<TimeSlot> found = slotRepo.findById(slotId);
      if (found.isEmpty() || !found.get().isOpen()) {
          failedBookings.incrementAndGet();
          log.warn("Booking failed: slot {} not found or already booked", slotId);
          return null;
      }
      TimeSlot ts = found.get();
      if (!slotRepo.markBooked(slotId, ts.getVersion())) {
          failedBookings.incrementAndGet();
          log.warn("Booking failed: version conflict on slot {} (concurrent booking detected)", slotId);
          return null;
      }
      // ... save appointment ...
      try {
          notifResult = notifClient.send(notif);
      } catch (Exception e) {
          log.error("Notification failed for appointment {}: {}", app.getAppId(), e.getMessage());
          notifResult = "NOTIFICATION_ERROR";
      }
      successfulBookings.incrementAndGet();
      log.info("Booking confirmed: appointmentId={} student={} advisor={}",
              app.getAppId(), studentName, ts.getAdvisorName());
      return notifResult;
  }


--- HealthController.java ---
// GET /health reads the live counters and open-slot count, returning them as a single JSON object.

  @GetMapping("/health")
  public Map<String, Object> health() {
      Map<String, Object> response = new LinkedHashMap<>();
      response.put("status", "UP");
      response.put("bookings_total",     appointmentService.getSuccessfulBookings());
      response.put("bookings_failed",    appointmentService.getFailedBookings());
      response.put("bookings_attempted", appointmentService.getTotalAttempts());
      response.put("slots_available",    timeSlotService.getOpenSlots().size());
      return response;
  }
